# Research and evidence standard

The project aims to make spatial algorithms understandable without sacrificing technical accuracy.

## Evidence hierarchy

Prefer, in order where relevant:

1. Original papers and formal specifications.
2. Maintainer documentation and source code for the implementation being discussed.
3. Textbooks and established technical references.
4. Peer-reviewed surveys and comparative studies.
5. Reproducible independent experiments.
6. Practitioner explanations, used as context rather than sole evidence for mathematical claims.

A source's position in this list is not an automatic guarantee of correctness. Explain why a source supports the claim.

## Citation record

For each important reference, record:

- author or responsible organisation;
- title;
- publication or version date;
- DOI or stable URL;
- access date for web documentation;
- the exact claim or section it supports;
- whether it is primary, implementation documentation or secondary explanation.

## Claims and uncertainty

Label material clearly when it is:

- a mathematical or formally specified property;
- a behaviour of a named software implementation and version;
- an empirical observation from a stated experiment;
- a practical recommendation;
- an open question or disputed claim.

Do not present a benchmark from one machine or dataset as a universal ranking.

## Reproducibility

Record environment, versions, input characteristics, parameters, CRS, units, precision model, random seeds and hardware where they materially affect results.

## Corrections

When an error is found, correct the canonical record and preserve a short change note. If a previously published explanation materially changes, identify the affected edition or release. Do not silently rewrite history.

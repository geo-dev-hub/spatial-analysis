# Try the ideas yourself

Exercises are where an explanation becomes something you can use. They should help a reader predict, test, explain, implement and eventually question a method.

## How exercises are organised

Exercises should link to a canonical method record and identify the knowledge they expect. A useful progression is:

1. **Notice:** identify the idea in a small example.
2. **Predict:** work out what should happen before running code.
3. **Trace:** follow the method one step at a time.
4. **Change:** alter an input, parameter or assumption and observe the result.
5. **Build:** implement a small part or compare two approaches.
6. **Investigate:** design a test, find a limitation or ask a new research question.

Not every topic needs six exercises. Choose the progression that fits the method.

## Exercise writing standard

Every exercise should state:

- the task in plain language;
- any required input or starter file;
- what the learner should submit or observe;
- hints, if useful;
- how to check the result;
- whether a solution is public or held back for a guided edition.

Do not make an exercise depend on an unavailable dataset, paid software or unexplained setup. Where a solution is provided, explain the reasoning rather than only showing the final answer.

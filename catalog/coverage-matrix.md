This matrix connects the original compendium to the work published in this repository. It is deliberately conservative: a topic is not marked researched or implemented just because its name appears in the source transcription.

**Status key**

- **Captured** — the source text is preserved in the page transcription.
- **Mapped** — the original section is indexed and its scope is visible.
- **In progress** — at least one canonical record or implementation exists, but the section is not comprehensively covered.
- **Not started** — no reviewed canonical coverage has been published yet.

## What this tells us

The repository now has a connected geometry foundation, a spatial-index foundation and a filter-and-refine spatial-join lesson, alongside a researched spatial-autocorrelation sequence. It still does not cover the breadth of the 47-page source. The next stage is not to create hundreds of shallow pages. It is to audit the source section by section, identify the right record type, verify names and references, and build connected explanations with examples.

Sections 11, 13, 15, 18, 19, 20, 21 and 22 carry explicit source warnings about remembered or representative additions. Section 12 also includes methods drawn from adjacent fields. Keep those warnings attached to the relevant intake material until each entry has been checked.

## Section 7 implementation note

The ELECTRE I-style package now contains two deliberately separate stages: pairwise relation construction and exact small-instance kernel enumeration. The kernel enumerator checks internal and external stability, reports every kernel, and explicitly reports when no kernel exists. It is exhaustive and capped at 20 alternatives by default; it does not perform cycle reduction or produce a total ranking. See the [method record](../methods/electre-outranking.md), [implementation contract](../implementations/python/electre-i/README.md), [kernel exercise](../exercises/electre-i-kernel.md) and [kernel lab](../notebooks/electre-i-kernel-lab.ipynb).


## Section 9 implementation note

The first local-frame package now connects geodetic longitude/latitude/ellipsoidal height to ECEF XYZ and local East-North-Up coordinates, including the inverse ENU-to-ECEF rotation. It reproduces the published EPSG:9836 example, has tests, an intern walkthrough, an exercise and a visual lab. Geoid/vertical-datum conversion, dynamic reference frames and epoch propagation remain outside scope. See the [lesson](../algorithms/geodesy/ecef-enu.md) and [package](../implementations/python/ecef-enu/README.md).


## Section 2 implementation note

Ripley's K/L now includes the rectangular-window translation correction and a conditional homogeneous-CSR simulation workflow. The latter returns pointwise quantile bands and a separate global studentised maximum-deviation Monte Carlo p-value across a preselected radius interval. Pointwise bands are not simultaneous global envelopes. Isotropic/border corrections, inhomogeneous point-process models, network KDE and specialist rank-envelope procedures remain open. See the [lesson](../algorithms/statistics/ripley-k.md), [package](../implementations/python/ripley-k/README.md), [exercise](../exercises/ripley-k-envelopes.md) and [lab](../notebooks/ripley-k-lab.ipynb).


## Section 6 implementation note

Maximal covering now has a tested exact small-instance solver, intern walkthrough, exercise and visual lab. It opens at most p facilities and maximizes non-negative weighted demand within a supplied threshold. It does not model capacity, queues or stochastic service. See the [lesson](../algorithms/optimization/maximal-covering.md) and [package](../implementations/python/maximal-covering/README.md).


The discrete p-center addition includes an exact small-instance minimax solver, tests, intern walkthrough, exercise and visual lab. It reports the selected facilities, worst assignment cost and nearest-site assignment for every demand row. It has no capacity, uncertainty or equity constraints. See the [lesson](../algorithms/optimization/p-center.md) and [package](../implementations/python/p-center/README.md).


## Section 3 implementation note

The standalone IDW package supplements the combined interpolation lesson with a dependency-free implementation, coincident-observation policy, optional neighbourhood restrictions, tests, intern walkthrough and an interactive notebook. It uses Euclidean distance in caller-supplied coordinate units and does not fit the power parameter or estimate uncertainty. See the [lesson](../algorithms/interpolation/inverse-distance-weighting.md) and [package](../implementations/python/inverse-distance-weighting/README.md).


The location set-covering package adds an exact small-instance solver that minimizes the number of sites needed to cover every demand row within a supplied threshold. It reports infeasible demand rows and deterministic assignments; it has no capacity or reliability model. See the [lesson](../algorithms/optimization/set-covering.md) and [package](../implementations/python/set-covering/README.md).


The capacitated p-median addition includes a small exact enumerator, capacity-feasibility tests, a step-by-step intern walkthrough, an exercise and a visual lab comparing the unconstrained and constrained assignments. Demand quantities consume capacity; separate objective weights affect assignment cost. The implementation requires indivisible demand and deterministic scalar capacity and makes no queueing or service-level claim.


The Section 6 accessibility-equity addition provides a descriptive diagnostics package with unit tests and visual notebook: population-weighted Lorenz curves and Gini, lower-tail quantiles, minimum-standard shortfall and group mean gaps. It explicitly distinguishes inequality measurement from normative judgments about fairness; the chosen groups, opportunities and minimum standard remain policy decisions.


The Section 6 equity-constrained maximal-covering addition provides an exact tiny-instance model that maximises covered objective weight subject to population-weighted minimum coverage floors for each caller-defined group. It includes separate demand and objective weights, infeasibility handling, tests, an intern walkthrough, exercise and executable lab. The group definitions and floors remain explicit policy choices; this is not a general fairness optimiser.


The Section 6 backup-coverage extension adds an exact small-instance r-covering solver, tests, intern walkthrough, exercise and executable notebook. It reports how many selected candidate facilities lie within the threshold for each demand row. It does not estimate failure probabilities or operational reliability, and shared dependencies must be examined separately.


The Section 6 queueing extension adds a dependency-free M/M/c implementation using Erlang-C, tests for the M/M/1 closed form, server sensitivity, Little's law and stability, plus an intern walkthrough, exercise and notebook. It is a stationary FCFS model with Poisson arrivals, exponential service and identical servers; it does not replace travel-time accessibility or model time-varying arrivals.
